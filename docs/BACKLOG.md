## 🚀 성능

### P1. 헬퍼 수식 경량화 (품목 선택·드롭다운 속도)  ← "C"로 논의됨
- **무엇:** Transaction의 `B7`(위치별 현재고), `W1`(FROM 후보)이 **모든 버킷마다 `BYROW(…SUMIFS(Inventory…))`** 를 돌린다(버킷수 × 재고행수).
- **왜:** `Inventory` 시트는 이미 (품목, 위치)별 1행으로 정규화돼 있어, SUMIFS 재합산 없이 **`FILTER`/`QUERY`로 해당 품목 행만** 뽑으면 훨씬 가볍다.
- **영향:** 품목(C4) 선택 반응, FROM 드롭다운 여는 속도. (Type 토글과는 무관 — 토글은 이미 최적화됨)
- **리스크:** 시리얼 품목은 위치당 여러 행(시리얼별 1행)이라 위치별 **합산 처리**(QUERY GROUP BY 등) 필요. 미묘한 케이스 있으니 단계적 교체 + 검증.
- **관련:** `Setup.js > setupInputSheet` 의 `B7`/`W1` 수식.

### P2. 제출마다 전체 원장 재연산 → 증분 업데이트
- **무엇:** `submitTransaction` 이 매번 `rebuildInv_`(Ledger 전체 재계산)를 호출.
- **왜:** Ledger가 커질수록 제출이 느려짐(현재 ~200건은 무난).
- **리스크:** 증분 로직은 정합성 관리가 까다로움. 규모 커지면 검토.
- **관련:** `Transaction.js > submitTransaction`, `Setup.js > rebuildInv_`.

### P3. updateDynamicUI 미세 최적화 (효과 작음)
- 회색 글자색 쓰기(`setFontColors`) 생략, 변경된 셀만 쓰기 등. 체감 미미 — 우선순위 낮음.

## 🔴 데이터 정합성

### D1. 음수 잔량(phantom negative) 정리
- **무엇:** Ledger 리플레이 시 일부 위치 순잔량이 **음수**로 나옴 (예: `GMP (통로)` ≈ −1279, `19-1-04` ≈ −189). 품목명/ID 불일치·과거 보정으로 추정.
- **왜:** `rebuildInv_` 는 품목ID+위치 순잔량이 **양수인 행만** Inventory에 기록 → 음수는 조용히 사라지지만, 위치 합계·감사 관점에선 왜곡.
- **할 일:** 어떤 품목/거래가 음수를 만드는지 진단 → 원장 보정 거래로 정정 or 매핑 정리.
- **관련:** `Ledger` 데이터, `Setup.js > rebuildInv_` / `getLedgerRows_`.

### D2. 자동 계산 시트 보호 미설정  ← 초기 리뷰 "C", 보류로 남김
- **무엇:** `Ledger / Inventory / Dashboard / Scrap` 은 스크립트가 100% 관리하는데 편집 보호가 없음 → 수기 편집 시 값 붕괴.
- **할 일:** 보호 범위(경고 또는 편집 잠금) 설정.

### D3. 품목명 표기 불일치 정리
- 같은 품목ID가 시점별로 다른 이름으로 기록됨(예: `ROUND CHARGER (C TYPE)` vs `(TYPE C)`). 시스템은 ID 기준이라 집계는 맞지만, 원장 가독성 저하. 표준 명칭 통일 검토.
