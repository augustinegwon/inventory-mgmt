## 🔧 유지보수 함수 (1회 실행)
스프레드시트 상단 **📦 Inventory** 메뉴에서 바로 실행 가능(`onOpen` 메뉴).
- **createTriggers()** — `updateDynamicUI` 를 '수정 시(onEdit)' 트리거로 자동 등록(중복 방지). 편집 시 시리얼/수량 칸 자동 제어가 동작하려면 필요.
- **migrateSerialsToText()** — 원장 E열에 숫자로 저장된 기존 시리얼(예: `123456789`)을 텍스트로 일괄 변환. 신규 입력은 이미 텍스트로 저장되므로 과거 데이터 정리용.
- **setupInputSheet()** — 입력폼 UI/수식 초기 설정(현재 배포 수식 기준).

## 🔴 High — 재고 정합성

### H1. 재고보다 많은 수량 출고(REMOVE/MOVE) 허용 → 음수 재고 발생
`submitTransaction()`은 FROM 위치의 현재고를 확인하지 않고 원장에 기록합니다.
- 실제 데이터: `LONG CHARGING CABLE (NEW)` @ `GMP WH A`
  - 행6: ADD **+1000**
  - 행7: REMOVE **−2000**  ← 재고 1000뿐인데 2000 출고됨(순간 잔고 −1000)
  - 행8: ADD **+3000**
- 제출 전에 `SUMIFS(To)−SUMIFS(From)` 로 FROM 잔고를 계산해, `qty > 잔고`면 차단해야 함.

### H2. 시리얼 품목의 중복 ADD / 미보유 시리얼 MOVE·REMOVE 미검증
- ADD(YES 시리얼): 이미 재고에 있는 시리얼을 또 ADD하면 중복 발생 → 사전 차단 필요.
- MOVE/REMOVE: FROM 위치에 그 시리얼이 실제로 있는지 서버 측(스크립트)에서 재확인 필요.
  현재는 드롭다운(X열)에만 의존 → 값 붙여넣기/직접입력으로 우회 가능.

### H3. 시리얼이 숫자로 저장되어 텍스트 시리얼과 타입 불일치
- 실제 데이터: `E5 = 123456789` (숫자), `E2 = '6R11285MA0462'` (텍스트).
- `updateDynamicUI`는 F3/F4/F6만 대문자화하고 **F5(시리얼)는 정규화하지 않음**.
- 숫자 시리얼은 앞자리 0 손실, SUMIFS 텍스트 매칭 불일치 위험.
- 제출 시 시리얼을 항상 문자열로 강제하고 공백 trim 필요.

## 🟠 Medium — 유효성/UX

### M1. `Code.gs`가 실제 배포 시트보다 구버전 (setupInputSheet 재실행 위험)
- 자세한 내용은 `docs/SHEET_STRUCTURE.md`의 ⚠️ 섹션 참고. 재실행 시 개선 수식이 깨짐.

### M2. FROM = TO 무의미 이동 미차단
- MOVE에서 출발지와 목적지가 같아도 통과 → 잔고 변화 0의 노이즈 기록.

### M3. 수량 검증이 양의 정수인지 확인 안 함
- `qty` 음수·0·소수·문자열 방어 없음. (시리얼 품목은 1 고정이나 일반 품목은 자유 입력)

### M4. USER 자유 입력 — Settings!H(USER 마스터)와 미연동
- 오탈자 작업자명이 그대로 기록됨. F9를 H열 드롭다운으로 제한 가능.
